Project

Conflict Resolution

A prototype web app that helps a table tennis tournament desk handle players whose events overlap in time.

  • Python
  • Flask
  • SQLite

Working prototype · Made-up data · Runs on my laptop only

Please read first

All data in this project is made up. There are no real players and no real tournament data. Two rules are assumptions to be confirmed with tournament staff. The app runs only on my laptop. There is no live link and no login yet.

01

Overview

At a big table tennis tournament, one player can be entered in several events that overlap in time. This app helps the tournament desk handle that. It records a conflict, suggests a play order for the player's events (for example start first, delay the next, finish last), tracks whether a player may be a no-show, and shows what is playing right now.

The app only suggests. The desk staff always decide.

Status: a working prototype, still being tested.

02

Why I built it

In summer 2026 I volunteered at the control desk of a national table tennis tournament. It was my first time in a very busy, stressful place, and I enjoyed solving problems and helping things run smoothly.

I saw that players are often entered in more than one event, that conflicts were handled on paper forms, and that a conflict reported late could delay the matches after it.

I built this prototype to practice making a full web app (forms, a database and a dashboard) around that problem. It is a personal project, for fun and for possible use at future tournaments, and all its data is made up.

03

My role

I planned the features and tested everything myself. Claude helped me plan and wrote the rule logic and the tests. GitHub Copilot wrote much of the page code from step-by-step prompts that I ran and checked.

04

What I built

  • A home page with live counts.
  • A live page that shows the events playing now, with the table, minutes played, players and conflicts. Click an event for details.
  • A desk list of conflicts with filters, and a page for each conflict.
  • A form to file a conflict, with a check for conflicts filed late.
  • A suggested play order for a player's events. The desk can edit it or reset it, and print a slip.
  • A player lookup with a heads-up banner.
  • Events and Players pages. Players can be added, edited, or imported from a CSV file with a preview.
  • Reports with charts and a CSV export.
  • A no-show countdown, and draft messages to a player or coach. The messages come from templates, not from AI.
  • A settings page, a demo clock, and dark and light themes.
  • 14 automated checks cover the sequence rules. All of them pass.

05

Tech

Python, Flask and SQLite. Plain HTML templates, with Bootstrap 5 and Chart.js kept on my computer so the app works offline. The fonts are Barlow Condensed and Inter.

06

Assumptions to be confirmed

Two rules in the app are my assumptions. I still need to confirm them with tournament staff.

  • The priority order of event types.
  • The 15-minute wait before a player is treated as a no-show.

The app stores both as settings marked "unconfirmed" instead of treating them as facts.

07

What is next

  • Confirm the two assumed rules with tournament staff.
  • Show the prototype to staff and ask how conflicts are really handled.
  • Keep testing, including on tablets and phones.
